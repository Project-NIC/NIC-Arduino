```
   NIC-MLA container ──▶ schema decode ──▶ rows ──▶ CSV / SQLite
```

> **Прочитайте сначала.** Это родственный проект **NIC-GLUE-IN** — та же идея,
> направленная в обратную сторону: GLUE-IN помещает строку данных *в* контейнер;
> GLUE-OUT проходит готовый контейнер и *выводит* его обратно в таблицу. Как и его
> родственник, это **рабочий пример плюс небольшой каталог вариантов**, а не
> фреймворк. Непреходящая ценность здесь снова —
> **[справочник по согласованию библиотек](#справочник-по-согласованию-библиотек)**
> — те же стыки, прочитанные с другого конца. Пример делает простейшую полезную
> вещь: открывает контейнер, декодирует каждую RAW-запись по её самоописывающей
> схеме и экспортирует всё в **CSV или SQLite**. **Сжатие NIC-DMD этот читатель
> распаковывает автоматически**; вне рамок остаётся только шифрование (NIC-KSF) —
> см. [ниже](#nic-dmd-встроено-и-nic-ksf).
> **NIC-VDE** — интерактивное средство просмотра тех же файлов; GLUE-OUT — путь
> экспорта без интерфейса.

## Справочник по согласованию библиотек

Библиотеки NIC намеренно *«глупые» и независимые*: MLA хранит непрозрачные
байты, VDE показывает файлы, KSF преобразует байты, DMD кодирует пакеты. Ни одна
из них не знает о других. Glue — это любой код, который выравнивает эти стыки.
GLUE-IN их *записывает*; вся работа читателя — *прочитать те же стыки обратно*.
Вот те, которые использует этот простой читатель:

| Стык | Что несёт контейнер | Что с этим делает читатель |
|---|---|---|
| **Вид записи** | MLA не несёт байта типа; у записи есть только бит `compressed` + `kf_back` (0 = ключевой кадр). Файлы однородны — типов TEXT/EVENT/CLASS нет, смысл задаётся схемой SCHEMA | выводит из них *вид* `raw` / `keyframe` / `delta`, затем декодирует в именованные значения: raw — напрямую по схеме, сжатые — через DMD (см. ниже); строка остаётся пустой, только если нет соответствия схеме |
| **Станция** | лог MLA хранит 1-байтный *индекс* станции; реальные номера находятся в таблице станций префикса | преобразует индекс → регион/номер, чтобы экспортируемые строки содержали реальные номера |
| **Время** | в логе MLA есть отдельное 4-байтное поле `timestamp`; поле схемы `log("datetime")` его описывает | время берётся прямо из заголовка лога — никогда не извлекается из блока данных |
| **Раскладка полей** | схема отделяет поля заголовка `log(...)` от полей полезной нагрузки `data(...)` | `mla_decode_payload` разбирает упакованный блок обратно на именованные масштабированные значения |
| **Целостность** | MLA защищает запись лога (и, при желании, блок данных) с помощью CRC16 | слоты с неверной CRC пропускаются ядром MLA при монтировании — читатель видит только зафиксированные записи |

Если файл соблюдал эту таблицу при записи (а любой GLUE-IN её соблюдает), он
читается обратно здесь и в NIC-VDE независимо от того, как было устроено всё
остальное.

## Что предоставляет пример

Намеренно небольшой читатель/экспортёр поверх одного контейнера MLA:

- **`GlueReader`** — открывает контейнер, после чего его можно перебирать или
  экспортировать. Он читает самоописывающие таблицы схемы/станций из префикса,
  декодирует полезную нагрузку каждого RAW-измерения в именованные
  масштабированные значения, преобразует индекс станции в её реальный
  регион/номер и сериализует всё в **CSV** или **SQLite**.

```python
from nic_glue_out import GlueReader

with GlueReader("weather.mla") as r:
    for rec in r:                          # decoded records, oldest first (raw + compressed)
        if rec.values is not None:         # decoded values (raw or DMD-decompressed)
            print(rec.timestamp, rec.station_label,
                  {n: v for n, _u, v in rec.values})
        else:                              # no schema match — show the raw bytes
            print(rec.timestamp, rec.kind, rec.block.hex())

    r.write_csv("weather.csv")             # → idx,time,unix,sta_idx,region,number,kind,length,<fields…>
    r.write_sqlite("weather.db")           # → a one-table SQLite database
```

```bash
python3 examples/weather_export.py          # builds a sample, then exports weather.csv + weather.db
python3 tests/test_glue.py                  # or: pytest tests/
```

## Варианты проектирования и практические советы

Это *возможности*, а не требования — выбирайте то, что подходит. Пример
реализует простейшее полезное чтение+экспорт; остальное — короткий список
настроек.

### 1. Цели экспорта — CSV или SQLite

Оба формата получаются из одних и тех же собранных строк; модуль `export` — это
«глупый» сериализатор (он ничего не знает о MLA). `to_csv()` возвращает байты
UTF-8; `to_sqlite()` возвращает базу данных из одной таблицы в виде байтов.
Передайте `raw=True`, чтобы сохранить целые числа в том виде, в каком они
передаются, вместо масштабированных физических значений схемы. Добавьте свою
цель (Parquet, JSON Lines, сокет), написав ещё одну функцию `to_…`, которая
принимает те же столбцы `(name, sql_decl)` + кортежи строк.

### 2. Откуда берётся метка времени

Читатель никогда не угадывает время: запись лога MLA имеет отдельное 4-байтное
поле `timestamp`, независимое от блока данных, а поле схемы `log("datetime")`
лишь *описывает* его. Поэтому читатель берёт его прямо из заголовка лога
(`rec.timestamp`) — блок данных содержит только полезную нагрузку датчиков. Это
точная противоположность стыку GLUE-IN «куда идёт метка времени»: время находится
в заголовке и никогда не дублируется в данных — как при записи, *так и* при
чтении.

### 3. Фильтрация

Читатель загружает весь контейнер в RAM (задокументированная модель для хоста) и
фильтрует на стороне хоста: `records(station=…, time_from=…, time_to=…)`. Индекса
на диске нет — это простой последовательный просмотр, дающий тот же результат,
что и фильтрация каждой записи.

### 4. Файлы без схемы

Контейнер, записанный без схемы, всё равно читается: каждая запись сводится к
одному столбцу `value` (текст как текст, крошечная полезная нагрузка как целое
число, иначе hex). Файл *со* схемой вместо этого получает по одному именованному
столбцу на каждое поле данных.

### NIC-DMD (встроено) и NIC-KSF

- **NIC-DMD (сжатие).** Если записывающая сторона использовала сжатый канал
  GLUE-IN, эти записи несут бит `compressed` (вид `keyframe` / `delta`). Этот
  читатель **распаковывает их автоматически**: он по порядку воспроизводит поток
  каждой станции через отдельный для станции `DmdDecoder(width)` (`width` = общая
  ширина данных по схеме), а затем пропускает результат через то же декодирование
  по схеме, что и путь raw, — поэтому сжатые и raw-строки экспортируются
  одинаково. Запись показывает пустые ячейки, только если для неё вообще нет
  сопоставления в схеме. **NIC-VDE** также позволяет просматривать такие файлы.
- **NIC-KSF (шифрование).** KSF находится на пути *передачи*, никогда — на пути
  хранения: отправитель шифрует перед передачей, получатель расшифровывает *до*
  того, как байты будут сохранены, — поэтому контейнер содержит открытый текст, и
  этому читателю ключ не нужен. Добавьте его на стороне приёма
  (`recv → ksf_decrypt → … → store`), зеркально стороне отправки GLUE-IN. См.
  NIC-GLUE-IN.

## Структура

```
nic_glue_out/       the glue example (GlueReader) + the dumb CSV/SQLite exporter
examples/           runnable, self-contained weather reader/exporter
tests/              read-back + decode + export tests
third_party/        vendored copy of NIC-MLA (see VENDORED.md)
tools/              sync_vendor.py — refresh third_party/ from canonical NIC-MLA/NIC-DMD
```

Чистый Python 3.10+, без внешних пакетов — зависимость включена в репозиторий
(vendored), экспортёр использует `sqlite3` из стандартной библиотеки.
