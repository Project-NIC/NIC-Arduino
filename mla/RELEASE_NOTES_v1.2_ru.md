# NIC-MLA v1.2 — финальная версия

*[English](RELEASE_NOTES_v1.2.md) · [Čeština](RELEASE_NOTES_v1.2_cs.md) · [Русский](RELEASE_NOTES_v1.2_ru.md)*

*Основной является английская версия.*

**v1.2 — последняя версия NIC-MLA, а вместе с ней и всего семейства NIC-Arduino.**
Семейство закрыто: каждый компонент читает 1.2, и ничего больше не планируется.
Станция, выросшая из этих инструментов (NIC-Heimdall), ведёт собственный
архив; MLA остаётся тем, для чего создавался, — для небольших устройств, которые пишут лог, и PC-инструментов,
которые его читают.

В этих примечаниях собрано всё, что появилось после v1.0, в одном месте. (Промежуточный тег v1.1
включён сюда же: у проекта практически не было пользователей, поэтому описывать нужно один
релиз, а не два.) Байт `version` в префиксе остаётся равным **1**.

## Что нового

- **Субсекундные метки времени.** Запись лога теперь содержит поле `subsec`
  (индекс отсчёта внутри секунды), поэтому MLA справляется с дискретизацией
  значительно выше 1 Hz — например, для MEMS-сейсмографа. Раньше время разрешалось только до
  целых Unix-секунд, что подходило для медленной телеметрии. Для логирования с точностью
  до целых секунд ставьте `subsec = 0`.
- **Компактная, консолидированная 16-байтная запись.** Старый байт `rec_type`/класса и
  байт выравнивания `reserved` удалены. Состояние кодирования теперь — один упакованный байт `flags`:
  **бит 7 = compressed**, **биты 0–6 = `kf_back`** (расстояние назад до
  соответствующего ключевого кадра; 0 = эта запись *является* ключевым кадром). Это освобождает место для
  `subsec` без увеличения записи.
  - MLA остаётся **независимым от кодека**: бит `compressed` означает лишь «передай
    полезную нагрузку слою кодека». *Какой* кодек / ключевой кадр / вариант — указано в
    собственном заголовке блока данных (NIC-DMD уже так делает), а не в MLA.
  - Файлы **однородны** — что означает полезная нагрузка, берётся из таблицы SCHEMA,
    а не из метки типа в каждой записи.
- **Надёжная ротация файлов.** Каждый файл после ротации монтируется независимо:
  - при повторном открытии он наследует таблицы/параметры формата предыдущего файла (больше никакой
    ротации в файл с пустыми таблицами);
  - MLA теперь **сообщает о событии ротации** (`MlaArchive.append` возвращает, произошла ли
    ротация; `will_rotate()` предсказывает её; срабатывает обратный вызов `on_rotate`), чтобы glue
    сжатого потока мог принудительно вставить ключевой кадр в начале каждого файла. Для
    RAW-данных это неважно.
- **Устойчивость префикса.** В хвост файла записывается побайтно идентичная **зеркальная копия**
  самоописывающего префикса; `mount()` переключается на неё, если
  основная копия по смещению 0 не проходит проверку CRC. Один плохой сектор в начале
  больше не «ослепляет» весь файл. (Область лога теперь заканчивается на `region_end =
  file_size − prefix size`.)

- **`subsec` — это позиция, и ею распоряжается glue.** Два байта непрозрачны для
  MLA (`subsec_lo` / `subsec_hi`). При частоте дискретизации, равной степени двойки, они содержат
  индекс отсчёта (кадра) внутри секунды, так что его размещение — это сдвиг, и никакая
  доля секунды никогда не хранится; позиция, которой нужно больше 16 бит,
  делится: грубая половина — в `subsec`, тонкая — в полезной нагрузке.
  Экспортёры (NIC-MSEED, NIC-IAGA) читают его как индекс кадра, а не как тик.
- **Восстановление после сбоя при монтировании.** `mount()` нейтрализует оборванный слот LOG на
  границе потока (перезаписывает его `0x00` — соглашение об отбрасывании) и проверяет
  блок данных самой новой записи, возвращая место после оборванной записи данных. Ограничено по объёму,
  идемпотентно — в чистый файл не делается ни одной записи, — и реализации на Python и C
  восстанавливают одни и те же оборванные входные данные в идентичные байты.
- **Усиленное аварийное восстановление.** `mla_recover` подтверждает границу записи по
  magic следующей записи, прежде чем выполнить повторную синхронизацию, а повреждённый основной префикс больше
  не определяет размер собственного зеркала — неповреждённое зеркало находится просмотром целых
  секторов.
- **Калиброванная схема.** Каждый дескриптор поля занимает 16 B и несёт собственную для поля
  мантиссу: `scale = mantissa × 10^exp10`, применяется при экспорте, сам архив
  остаётся необработанным. В словарь единиц добавлена `m/s²`. Тег таблицы схемы — **1**.
- **Раскладка datalogger** (`DESIGN-MLA-datalogger.md`): много профилей станций
  в одном файле; от раскладки с единой схемой отличается тегом по смещению 34.

## Совместимость

- Формат на диске изменился (раскладка записи + хвостовое зеркало). Файлы v1.0 не
  читаются v1.2, и наоборот. Байт `version` в префиксе остаётся равным 1.
- Побайтная идентичность между эталонной реализацией на Python и библиотеками на C (AVR / ARM / PC) —
  проверено с помощью `c/cross_check.py`.
