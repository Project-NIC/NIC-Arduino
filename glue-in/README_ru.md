# NIC-GLUE-IN

*[English](README.md) · [Čeština](README_cs.md) · [Русский](README_ru.md)*

*Основной является английская версия.*

**Связующий слой между библиотеками NIC — DMD, KSF, MLA, VDE — на стороне приёма / записи.**

---

[![License: MIT](https://img.shields.io/badge/License-MIT-red.svg)](https://opensource.org/licenses/MIT)

---

```
   sensor row / wire packet ──▶ [ optional NIC-DMD ] ──▶ NIC-MLA container
                                                                 │
                                                                 ▼
                                            NIC-VDE  (read-only viewer / export)
```

> **Прочитайте сначала.** Glue — *это то, что вы выстраиваете сами.* Существует
> много правильных способов связать эти библиотеки, и лучший из них зависит от
> вашего устройства, вашего канала связи и того, что вы хотите делать с данными.
> Поэтому этот репозиторий — **рабочий пример плюс каталог вариантов**, а не
> фреймворк, который вы обязаны принять. Непреходящая ценность здесь —
> **[справочник по согласованию библиотек](#справочник-по-согласованию-библиотек)**:
> небольшой набор стыков, в которых библиотеки должны договориться, записанный
> один раз, чтобы каждый мог в них разобраться. Направление чтения / экспорта —
> это родственный проект **NIC-GLUE-OUT**; **NIC-VDE** — средство просмотра.

## Справочник по согласованию библиотек

Библиотеки NIC намеренно *«глупые» и независимые*: MLA хранит непрозрачные
байты, DMD кодирует пакеты фиксированной ширины, VDE показывает файлы, KSF
преобразует байты. Ни одна из них не знает о других. Слой glue — это любой код,
который выравнивает эти стыки. Их всего несколько, и правильно согласовать их —
это и есть вся работа:

| Стык | Что предоставляет каждая сторона | Как они согласуются |
|---|---|---|
| **Бит сжатия + `kf_back`** | лог MLA v1.2 несёт 1-байтное поле `flags` (бит 7 = `compressed`, биты 0–6 = `kf_back`), но никогда его не интерпретирует; *какой* кодек используется, указано в собственном заголовке блока данных (байт 0 DMD), а не в MLA | glue устанавливает бит `compressed` (`False` для дословных строк, `True` для вывода DMD) и `kf_back`; виды записей — **raw** (без сжатия), **keyframe** (сжатая, `kf_back == 0`), **delta** (сжатая, `kf_back > 0`) |
| **Ключевой кадр** | ключевой кадр DMD = номер отсчёта `0` (3-битное поле; значение `7` зарезервировано для версии протокола) | glue считывает его обратно из блоба DMD (`blob[0] & 0x07 == 0` ⇒ ключевой кадр = отсчёт DMD 0) и помечает запись соответствующим образом |
| **Расстояние до ключевого кадра** | в логе MLA есть поле `kf_back`, которое он только переносит; читателям нужно найти соответствующий ключевой кадр | glue устанавливает `kf_back` = число записей назад до соответствующего ключевого кадра (`0` на самом ключевом кадре) |
| **Подсказка о периодичности ключевых кадров** | в префиксе MLA есть `keyframe_intv` (только метаданные); периодичность DMD внутренняя (`DMD_KEYFRAME_EVERY`) | по умолчанию в базовой библиотеке `0`; glue передаёт DMD периодичность, чтобы вызывающему никогда не приходилось её указывать (можно переопределить) |
| **`subsec` (два непрозрачных байта)** | лог MLA несёт поле `subsec` — два непрозрачных байта, которыми владеет glue (доли секунды, sub-**sec**ond, *и/или* подраздел, sub-**sec**tion / ротация); MLA не придаёт ему смысла | glue передаёт `subsec` без изменений в `log_raw` / `CompressedChannel.log` (вызывающий сам составляет 16-битное значение или два байта); на станции NIC вызывающий записывает **индекс кадра** — см. [варианты получения времени](#1-откуда-берётся-метка-времени) |
| **Ширина пакета** | DMD требует, чтобы все пакеты в потоке имели *одинаковую* ширину (delta) | ширина принадлежит **каналу** (4..255 B) и проверяется при каждом `log()`; разные каналы могут различаться |
| **Идентичность потока** | идентичность потока в файле — *это* его индекс станции MLA; никакой другой пометки для каждой записи MLA не нужно | читатель различает потоки по станции и читает `kf_back`, чтобы найти ключевой кадр каждого потока; один компрессор DMD без состояния + N крошечных контекстов на поток (`ChannelBank`) удерживают дельты в порядке |
| **Ротация → ключевой кадр** | MLA v1.2 (2b) сообщает о событии ротации + `will_rotate()`, чтобы каждый файл после ротации можно было декодировать независимо | `GlueArchiveLogger` + `ChannelBank` связывают это от начала до конца: поток, который *вызывает* переход на новый файл, проверяет `will_rotate(pkt_len+1)` **до** сжатия и сбрасывается, так что эта запись становится ключевым кадром (дельта никогда не пересекает границу файла); каждый *другой* поток сбрасывается через `on_rotate` → `reset_all()`. Таким образом, первая запись каждого потока в каждом файле — ключевой кадр (для RAW-данных неактуально) |
| **Станция** | лог MLA хранит 1-байтный *индекс* станции (1..255), реальные номера находятся в таблице станций префикса | соответствием индекс ↔ регион/номер владеет glue/`MlaStationTable` |
| **Время** | в логе MLA есть отдельное 4-байтное поле `timestamp`; поле схемы `log("datetime")` (пресет `4 B unix_s`) его *описывает* | время находится в заголовке лога и **не** дублируется в блоке данных — см. [варианты получения времени](#1-откуда-берётся-метка-времени) |
| **Раскладка полей** | схема отделяет поля `log(...)` (заголовок) от полей `data(...)` (полезная нагрузка); `mla_decode_payload` распаковывает блок | разделение log/data *и есть* карта того, «что идёт в заголовок», а «что остаётся в блоке» |
| **Целостность** | MLA защищает запись лога (и, при желании, блок данных) с помощью CRC16 | выберите `MLA_CRC_FULL` (рекомендуется), `MLA_CRC_DATA` или `MLA_CRC_NONE` при форматировании |

Если ваш собственный glue соблюдает эту таблицу, ваши файлы проходят полный цикл
через NIC-VDE и NIC-GLUE-OUT независимо от того, как вы устроите всё остальное.

## Что предоставляет пример

Намеренно небольшой даталоггер поверх одного контейнера MLA:

- **`GlueLogger`** — `log_raw()` / `log_event()`: принять строку, сохранить строку в
  **одном** контейнере MLA. Повседневный случай; работает с любым числом станций.
- **`GlueArchiveLogger`** — тот же API записи, что и у `GlueLogger`, но поверх
  **ротируемого** `MlaArchive` (`MLA00000.MLA`, `MLA00001.MLA`, …). Он связывает стык
  ротация→ключевой кадр от начала до конца, так что **каждый файл декодируется
  независимо** (см. ниже); таблицы схемы/станций также записываются в префикс
  каждого файла.
- **`CompressedChannel`** — `open_compressed_channel(station, pkt_len)`, затем
  `.log(ts, row)`: необязательное сжатие NIC-DMD для **одного потока фиксированной
  ширины**, бит `compressed` / `kf_back` заполняются автоматически.
- **`ChannelBank`** — `open()` / `log()` / `reset_all()` / `on_rotate()`: один
  компрессор DMD без состояния + N крошечных контекстов на поток, по одному
  `CompressedChannel` на индекс станции MLA. Создайте его поверх `GlueArchiveLogger`,
  и стык ротации подключится сам; первая запись каждого потока в каждом файле —
  ключевой кадр.

```python
from nic_glue_in import GlueLogger, MlaSchemaBuilder, MlaStationTable

schema = MlaSchemaBuilder(); schema.log("datetime")          # describes the log timestamp
for n in ("temp", "humidity"): schema.data(n, unit="raw", width=2)
stations = MlaStationTable(); stations.station(region=55, number=25000)

with GlueLogger("out.mla", schema_table=schema.table(),
                station_table=stations.table()) as log:
    log.log_raw(ts, station=1, data=row_bytes)            # classic path (raw)
    log.log_event(ts, station=1, text="PING")             # just an uncompressed record

    ch = log.open_compressed_channel(station=1, pkt_len=4) # optional compression
    ch.log(ts, row_bytes)                                  # → compressed, kf_back (keyframe/delta)
```

С ротацией, причём каждый файл декодируется независимо:

```python
from nic_glue_in import GlueArchiveLogger, ChannelBank

with GlueArchiveLogger("/data", schema_table=schema.table(),
                       station_table=stations.table()) as log:
    bank = ChannelBank(log)                       # auto-wires the rotation seam
    for ts, row in stream:
        bank.log(station=1, pkt_len=4, timestamp=ts, row=row)   # rotates + keyframes itself
```

```bash
python3 examples/weather_datalogger.py     # writes weather_raw.mla + weather_dmd.mla
python3 tests/test_glue.py                  # or: pytest tests/
```

## Варианты проектирования и практические советы

Это *возможности*, а не требования — выбирайте то, что подходит. Пример
реализует простейший вариант каждой из них; остальное намечено, чтобы вы могли
его расширить.

### 1. Откуда берётся метка времени

Запись лога MLA имеет отдельное 4-байтное поле `timestamp`, независимое от
непрозрачного блока данных, и его описывает поле схемы `log("datetime")`. Поэтому
время относится **к заголовку лога** и никогда не дублируется в данных. Как оно
туда попадает — решать вам:

- **(a) Собственные часы glue (RTC / время приёма).** Самый простой вариант: glue
  проставляет на каждой записи время, когда он её *получил / записал*, по RTC
  устройства. Пакет несёт только данные датчиков. Именно так поступает пример —
  `timestamp` является аргументом `log_raw` / `Channel.log`.
- **(b) Извлекается из заголовка пакета.** Сам пакет из канала связи несёт время в
  виде заголовка (например, `[datetime 4 B unix_s][sensors …]`). При приёме glue
  отрезает заголовок — **где именно, ему подсказывают ширины полей log в схеме**, —
  записывает его в `log.timestamp`, а оставшиеся байты датчиков сохраняет как блок.
  «Заголовок переезжает в лог». DMD ничего не знает о времени; смещение знает
  именно *схема*.
- **(c) Передаётся вызывающим.** Тот вышестоящий слой, который уже знает
  достоверное время, передаёт его напрямую.

> Процедура для (b), приём из канала связи:
> `recv(blob)` → `DmdDecoder.decompress(blob)` → `packet` →
> `t = int.from_bytes(packet[:4], "little")` → `data = packet[4:]` →
> `MlaCore.append(t, station, data, compressed=…, kf_back=…)`.

**Доля секунды помещается в `subsec` как индекс, а не как дробь.** Целая секунда —
это `timestamp`; позиция внутри неё — индекс кадра на сетке со степенью двойки,
записываемый непосредственно в `subsec` (станция NIC: `timestamp` = абсолютная
секунда, `subsec` = кадр). Нигде не хранится доля секунды, и ничто не делит, чтобы
её восстановить, — экспортёр превращает индекс во время как `subsec / rate`, точно,
поскольку частота является степенью двойки. Если один кадр несёт несколько
отсчётов, более точная позиция остаётся в блоке данных, который схема уже описывает.

### 2. Хранить сжатым или сжимать только при передаче?

1-байтный заголовок DMD и его свойство «никогда не увеличивает размер более чем на
1 B, никогда не теряет данные» делают хранение в сжатом виде безопасным. Два
подхода:

- **Хранить RAW (в распакованном виде).** Если вы получили сжатый пакет,
  распакуйте его при приёме и сохраните байты датчиков дословно (запись **raw** —
  бит `compressed` остаётся сброшенным). Читателям не нужен кодек; VDE декодирует
  напрямую по схеме. Стоит места на диске, зато даёт простоту.
- **Хранить сжатым (запись **keyframe**, затем записи **delta**).** Держите блоб DMD
  в блоке данных (бит `compressed` установлен; `kf_back == 0` обозначает ключевой
  кадр, `kf_back > 0` — дельту). Файлы меньше. Платой становится **произвольный
  доступ**: поскольку каждый дельта-пакет вычисляется относительно предыдущего,
  чтобы открыть запись *i*, нужно воспроизвести поток вперёд от его ключевого
  кадра — именно для этого и нужен `kf_back` (он сообщает читателю, как далеко
  назад находится ключевой кадр). Для одного канала это один небольшой буфер
  «предыдущего отсчёта» и проход от ключевого кадра.

### 3. Несколько потоков

`CompressedChannel` — это один поток DMD = один индекс станции + одна
фиксированная ширина. Модель — **один компрессор DMD без состояния + N крошечных
контекстов на поток**, и именно это предоставляет `ChannelBank`: он управляет
несколькими `CompressedChannel`, по одному на индекс станции MLA (`open` / `log` /
`reset_all` / `on_rotate`). Можно открыть много каналов (до 255), но дельта даёт
выигрыш только *внутри* потока, поэтому сжатие десятков независимых станций в
основном лишь расходует RAM (по одному буферу предыдущего отсчёта на каждую).

При ротации файлов (NIC-MLA 2b) подключите `MlaArchive(dir, on_rotate=bank.on_rotate)`
(или проверяйте `arch.will_rotate(n)` перед кодированием): `ChannelBank.on_rotate`
вызывает `reset_all()`, так что первая запись каждого потока в новом файле —
ключевой кадр, и каждый файл после ротации декодируется независимо. Пример
сжимает одну станцию, чтобы показать, что это работает; всё остальное
записывается в raw.

### 4. Шифрование (NIC-KSF)

KSF намеренно **не** входит в путь хранения — хранить шифротекст в контейнере
значит работать не на том уровне (конфиденциальность при хранении оставьте
доверенной платформе). Его место — путь **передачи**: отправитель шифрует
(при необходимости сжатый) пакет перед передачей, получатель расшифровывает его
перед приёмом в хранилище. Ключом владеют обе стороны; контейнер его никогда не
видит.

> Порядок в канале (отправитель): `pack row → [DMD compress] → [KSF encrypt] → transmit`.
> Получатель зеркально повторяет его: `recv → [KSF decrypt] → [DMD decompress] → store`.
> Обратите внимание: DMD считает зашифрованные байты случайными и сохраняет их
> как RAW (+1 B), поэтому **сжимайте до шифрования**, никогда не после.

## Даталоггер (несколько профилей)

Запись станций нескольких типов в один `.mla` (с разной раскладкой столбцов): передайте таблицы даталоггера как `schema_table` и используйте `log_raw(station, data)`. См. `DataloggerBuilder` и `tests/test_datalogger.py`; полная спецификация — в NIC-MLA `DESIGN-MLA-datalogger.md`.
